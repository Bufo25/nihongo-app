# Японский с нуля

PWA-трекер 3-месячного плана изучения японского. Работает на ПК (Windows 11) и телефоне, офлайн, данные хранятся локально на устройстве.

## Экраны

- **Сегодня** — задачи недели, обязательные блоки дня, блоки «3 раза в неделю», кнопка «Плохой день», подсказка «Если пропустил» после перерыва, разбор недели в выходной.
- **Серия** — счётчик дней подряд, лучшая серия, календарь с крестиками.
- **План** — 12 недель, текущая подсвечена, продление недели на 7 дней.
- **Прогресс** — уроки Minna 1–14 («в процессе» / «пройден») и число слов в Anki с историей и отметками 400 / 600 / 800.
- **Тренажёр каны** — хирагана и катакана (основные, с точками, сочетания), выбор из 4 или ввод чтения кириллицей (Поливанов) либо латиницей (Хэпбёрн). Слабые знаки выпадают чаще, есть таблица «что уже знаю».
- **Чекпоинты** (с подсказками из данных: уроки, слова, кана), **Разбор недели**, **Дневник**, **Ресурсы**, **Настройки** (Google Drive, Anki, напоминание, дата старта, установка).

## Правила подсчёта

- Обязательные блоки по неделям: кана (недели 1–4), Anki и Wagotabi (с недели 2), дневник (с недели 9). Учебник и шэдоуинг (с недели 5) — 3 раза в неделю, на серию не влияют.
- ✕ — сделана вся обязательная часть. Лёгкий день — «плохой день» или сделано не всё.
- Один лёгкий день в календарную неделю (пн–вс) засчитывается и не рвёт серию. Пустой день или второй лёгкий день за неделю обнуляют серию. Незаконченный сегодняшний день серию не рвёт.

## Напоминание

1. Пока приложение открыто или свёрнуто — проверка раз в минуту.
2. В установленном приложении в Chrome/Edge (Android, Windows) — Periodic Background Sync, примерно раз в час, даже если приложение закрыто.
3. Запасной вариант — файл .ics с ежедневным событием для календаря.

На iPhone фоновых проверок нет, поэтому там лучше использовать календарь.

## Синхронизация ПК и телефона

Копия данных лежит в облаке — в **закрытом репозитории GitHub** (по умолчанию) или в **Google Drive**. Слияние поэлементное: у каждого дня, записи, урока, знака каны есть время изменения, побеждает более свежее, удаления тоже переносятся. Напоминание и подключения (Anki, токены) у каждого устройства свои. Синхронизация идёт сама: при запуске, после отметок, при возврате в приложение.

### GitHub (закрытый репозиторий)

Данные — файл `nihongo-data.json` в отдельном закрытом репозитории, через GitHub Contents API прямо из браузера. Если файл успел измениться с другого устройства, приложение перечитывает его и сливает заново.

1. [github.com/new](https://github.com/new): репозиторий `nihongo-data`, **Private**.
2. [Fine-grained токен](https://github.com/settings/personal-access-tokens/new): Repository access → Only select repositories → `nihongo-data`; Permissions → Repository permissions → **Contents: Read and write**; срок — год или без срока.
3. В приложении: Настройки → Синхронизация → GitHub → `логин/nihongo-data` и токен. На каждом устройстве.

Токен — как пароль: не добавлять в репозиторий приложения и в переменные сборки (сайт публичный). Открытый репозиторий для данных приложение не примет.

Яндекс Диск пробовали: загрузка из браузера работает, а сервер скачивания (downloader.disk.yandex.ru) запросы из браузера не пускает, поэтому без своего сервера-посредника он не подходит.

### Google Drive

Файл в скрытой папке приложения (appDataFolder), право `drive.appdata`. Вход в браузере действует около часа, потом нужно одно нажатие «Синхронизировать».

1. [console.cloud.google.com](https://console.cloud.google.com/) → создать проект.
2. APIs & Services → Library → **Google Drive API** → Enable.
3. Google Auth Platform: External, режим **Testing**, свою почту — в Test users.
4. Clients → Create client → **Web application**, в Authorized JavaScript origins — адрес приложения.
5. Client ID — в настройки приложения или в переменную репозитория `GOOGLE_CLIENT_ID`.

## Anki (AnkiConnect, только ПК)

В Anki установить дополнение AnkiConnect (код `2055492159`), в его настройках добавить адрес приложения в `webCorsOriginList`, в приложении включить «Подтягивать из Anki». Считаются заметки колоды (`KaishiRu*` по умолчанию), у которых есть хотя бы одна не новая карточка.

## Разработка

```bash
npm install
npm run dev        # локальный сервер разработки
npm test           # тесты логики (серия, недели, слияние, кана)
npm run test:e2e   # браузерные тесты (нужна сборка): основной сценарий, синхронизация GitHub и Google
npm run build      # сборка в dist/
npm run preview    # проверить сборку с service worker
```

Стек: Vite + Preact + TypeScript, vite-plugin-pwa (injectManifest, свой service worker в `src/sw.ts`).

## Публикация

Для установки на телефон приложение должно открываться по HTTPS. Workflow `.github/workflows/pages.yml` при пуше в `main` прогоняет тесты (логика и браузерные) и, если всё зелёное, публикует приложение на GitHub Pages (в настройках репозитория: Settings → Pages → Source: GitHub Actions). Подойдёт и любой статический хостинг: достаточно загрузить папку `dist/`.
